### Mandatory first-response verification
1. **Payment integrity first:** compare active payment routes, database schemas, Yoco verification API, and genuine order ownership. Add tests before changing transactions. Avoid exposing provider keys or live customer records.
2. **Separate exposure from exploitability:** `SEC-03/04/05` are advisory categories. Some are intentional public interfaces. Don't revoke the complete class.
3. **Enable password leak protection in the Supabase Auth settings** if the project's plan allows it; it isn't currently configurable through this audit tool.
4. **Apply GitHub branch protection through repository settings** with required checks. Protecting a route by renaming `/admin` alone is NOT authorization.
5. **P0 is a risk priority, not a claim that every item has been exploited.** Record exact before/after, test evidence, reviewer, deployment, rollback and next verification date.
