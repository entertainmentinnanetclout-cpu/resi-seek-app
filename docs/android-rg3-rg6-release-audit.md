# ResKonnect Android RG3–RG6 release audit — 2026-09-19

**Target:** `org.reskonnect.app`, Android 1.1.3 / Play versionCode 6; source PR #134. This document distinguishes automated source/build evidence from actual hardware and external-provider validation. **Do not present an unsigned readiness AAB as a Play-ready release.**

## Scope and verified implementation

- **RG1 retained:** Native signed-in student entry is the full lazy-loaded dashboard, without the duplicate ResKonnect/Portals/Logout strip. Website retains public landing and appropriate account home. Existing native first-run, per-user profile-to-accommodation-to-applications spotlight tour is preserved.
- **RG3 location:** Native foreground permission flow, bounded first-fix fallback, manual campus selection when unavailable, campus/GPS-local residence suggestions ranked by locality before valid-photo presence. Native maps use a separate lazy-loaded vector/2D path; Google Photorealistic `Map3DElement` must never mount in the Android WebView. The 3D-renderer crash cannot be marked eliminated without a real-device Android vitals or logcat check.
- **RG4 inbox:** Existing `notifications` remains the only canonical account inbox. Authenticated full details at `/dashboard/updates?id=<id>` query `id` and `user_id`; bell and full list open the same detail route. Related actions are allowlisted. A single owner-scoped realtime feed deduplicates incoming alerts. Applications trigger an idempotent submitted/status-updated notice; administrator feedback-only history inserts create a separate event without exposing the note on the lock screen. These database changes were applied to `mefjzkhobkltlbmhusdh` with follow-up unique-index inference fix.
- **RG4 Android on-device alert:** `POST_NOTIFICATIONS` requested only when user opts in from notification settings. Local notification body is generic; opening resolves to the authenticated full detail route. This is **foreground, app-running** notification delivery, not Firebase Cloud Messaging background push.
- **RG5 premium dashboard:** Native-only branded hero and colored action tiles paint without an additional dashboard RPC. Live user-specific My ResKonnect command centre follows below; no new fake profile/application data or placeholder listing is introduced. Existing full-page dashboard remains on web.
- **RG6:** Readiness CI verifies package identity, SDK 36 target/compile, manifest permissions, native plugin parity, TypeScript, app auth/session fixture, production web build, Android AAB compile, security/SEO gates. Signed release CI uses protected original keystore and checks `jarsigner` and SHA-256; it must be run separately after integration/physical-device checks.

## Remaining release blockers / external setup

1. **Firebase background push:** No `android/app/google-services.json` or verified FCM sender configuration was present in the inspected repository. `nativePushNotifications=false` is intentionally truthful. A device-token registry is provisioned but not yet wired to native FCM registration or a credentialed background-delivery worker. Do not claim push alerts arrive while the app is killed/backgrounded. Complete the Firebase project, Android app with the exact package ID, Android signed client configuration, server credential storage and authenticated token lifecycle plus real-device background delivery before advertising WhatsApp-like device push.
2. **Native device stability:** Install a *signed* internal testing build and test on the previously crashing tablet and a lower-memory phone: first login/full dashboard; close/reopen session; profile modal and spotlight guide; Android location permission granted/denied/offline/slow fix; nearby image-aware residence search; 3D open/orbit/close/reopen at least three times; app cold start and sign out. Collect Play Android vitals/`adb logcat` for any WebView renderer death, OOM, native crash or ANR. The map must degrade to 2D, not terminate the whole app.
3. **Notification permissions and account scope:** In Android 13+ grant/deny/disable device notification permission, use a test student to generate one application submission, one status transition, and one staff feedback-only event; check one matching account notification per event, realtime toast while open, native alert opt-in, complete detail, read count after open, notification isolation between two student accounts, no sensitive lock-screen detail or delivery to the previous signed-out user.
4. **Performance proof:** On low-memory hardware record cold-start-to-full-dashboard interactive time, dashboard navigation latency, location success/timeout, app memory around map open/close and crash-free sessions before claiming measured speed/stability improvements. Do not infer runtime performance solely from a faster skeleton/hero first paint.
5. **Play upload:** Confirm code 6 has not already been used in the Play Console; if it has, increase it before signing. Build and upload via Android Play Store Signed Release after CI and native acceptance. Version 1.1.2/code 5 remains separate from this source update.

## Release decision

Automated CI passing is a **source/build gate only**. This change set can merge as a staged source upgrade after CI if its limits are disclosed, but is **not a complete RG4 closed-app push implementation**, not evidence that Android 3D will never crash, and not a signed/published Play Store update. Those milestones require the external FCM configuration and physical-device evidence above.
